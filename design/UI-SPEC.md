## 3. 视觉 CI（V0.1 强制，后续每个阶段回归）

1. 校验基准文件存在、尺寸、格式和 SHA-256；失败即阻塞。
2. 固定 Chromium 版本、字体（含中文）、视口、DPR、语言、时区和测试数据；禁用动画、时间变化，等待字体及页面就绪。
3. Playwright 截图保存 actual.png。基准 WebP 解码为无损 PNG 后比较，不修改原始文件。
4. 外层 UI 与 mock 画面分别比较；用户于 2026-11-27 明确批准开发阶段（V0.1–V0.9）外壳整体与每个核心区域的逐像素差异均 <=15%；V1.0 最终发布/上线验收仍要求外壳及每个核心区域均 <=1%。像素色差阈值固定 0.1，关键边界偏差 <=2 CSS px；同时输出严格像素差异、diff.png、区域统计。真实远程内容区不作为产品外壳像素评分，但须单独测试尺寸、无裁切、连接与输入功能。报告必须明确被排除区域，不能把外壳结果冒充整图一致率。
5. 不许遮挡差异区域、未经批准扩大阈值、覆盖基准图、用整图作为网页背景、仅做静态截图或伪造按钮。基准变动需用户明确审批。
6. 必须验证项目切换、标签、分屏、全屏、远程接管、暂停/恢复/停止、CI 状态及交接状态的实际行为；视觉通过不能代替功能测试。
7. CI 发布原图/实际截图/diff/JSON 报告，适用的阶段门禁失败禁止进入下一阶段。报告必须同时记录开发与发布门槛的独立结果，开发通过不等于最终通过。普通 PR/push 使用 development；手动 Actions workflow_dispatch 可选 release，v1.* 标签 CI 强制 release。V1.0 必须在同一候选提交通过严格 release CI 并取得用户验收（原图对照及真实远程浏览器）后才能发布或部署；不允许使用 development 成功替代。
